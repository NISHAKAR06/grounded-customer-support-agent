# Grounded Customer Support Agent — Development Guide

## 1. Project Philosophy & Core Objective

The **Grounded Customer Support Agent** is a production-grade AI support operations system built as an enterprise support intelligence platform.

The central mission of this system is to handle customer support inquiries with provable grounding in historical resolved brand conversations, strict validation against hallucinations or policy violations, and an explainable decision engine that routes between automated handling (`AUTO_HANDLE`) and human intervention (`HUMAN_ESCALATION`).

### Primary Principles
1. **The Proof is Worth More Than the System**: Evaluation integrity takes absolute precedence over cosmetics. No fabricated metrics, no fake conversations, no data leakage, and no cherry-picked samples.
2. **Grounding in Historical Reality**: Responses generated by the agent must strictly derive from real, resolved interactions by the selected brand.
3. **Safe Escalation**: Knowing *when not to automate* is as critical as automating. Ambiguity, weak retrieval evidence, customer frustration, or low classification confidence must deterministically trigger escalation to human agents.
4. **Reproducibility**: Any reviewer or evaluator must be able to spin up the system and verify headline benchmarks within 15 minutes without requiring 3M raw tweets.

## 2. Phased Development Lifecycle & Deliverable Mapping

To maintain clean engineering hygiene, strict evaluation integrity, and direct adherence to production engineering specifications, development is structured into sequentially verified milestones under a strict **Zero-Mock Policy**:

| Phase | Identifier | Focus | Key Output Artifacts | Status |
| :--- | :--- | :--- | :--- | :---: |
| **Phase 0** | Project Foundation | Scaffolding, configuration, B2B SaaS layout, OOP service contracts, CI/CD | Base templates, settings, logging, core schemas | ✅ Completed |
| **Phase 1** | Dataset Exploration | Kaggle Customer Support on Twitter ingestion, schema validation, volume profiling | `notebooks/01_data_exploration.ipynb`, EDA metrics | ✅ Completed |
| **Phase 2** | Brand Selection | Evidence-backed selection of `@AppleSupport` (volume, resolution rate, multi-turn) | `docs/BRAND_SELECTION.md`, responsive UI across devices | ✅ Completed |
| **Phase 3** | Conversation Reconstruction | Thread graph traversal, multi-turn stitching, text cleaning, paginated inbox | `scripts/data/preprocess_conversations.py`, 3,423 threads | ✅ Completed |
| **Phase 4** | Intent Taxonomy & Disambiguation | 7-class MECE taxonomy, precedence rules, interactive UI playground & REST API | `data/taxonomy/intent_taxonomy.json`, `/methodology` UI | ✅ Completed |
| **Phase 5** | Golden Evaluation Set | 150–250 hand-labelled real examples sampled from `@AppleSupport` dialogues | `data/golden/golden_set.jsonl`, `data/golden/README.md` | ✅ Completed |
| **Phase 6** | Baselines & Intent Benchmark | Trivial baseline (Majority) + Simple baseline (TF-IDF LogReg) vs Final Model | Per-class F1, Confusion matrix, trained weights | ✅ Completed |
| **Phase 7** | Real Historical Retrieval | Dense MiniLM embeddings + FAISS vector store of resolved cases | `models/embedding_model/faiss.index`, Recall@1/3/5, MRR | ✅ Completed |
| **Phase 8** | Grounded Generation & Validation | Evidence prompt conditioning, multi-provider LLM generation, deterministic claim checks | Grounded prompt builder, multi-barrier `ResponseValidator` | ✅ Completed |
| **Phase 9** | Evaluation Harness & LLM Judge | Automated test set benchmark, LLM-as-a-Judge, and human agreement metrics | Benchmark table, Cohen's Kappa, judge rubric | ⏳ Next |
| **Phase 10**| Engineering Report & Reproducibility | 6-page report (5 failure modes, "Misleading headline", 15-min reproduction script) | `report/REPORT.md`, `scripts/run_evaluation.py` | Planned |

### Zero-Mock Policy
1. **Real Data Only**: All conversations, intents, resolutions, and evaluations are derived strictly from real `@AppleSupport` customer dialogues in the Kaggle Twitter corpus.
2. **Deterministic Evaluation**: No fabricated metrics, no simulated dummy dialogues in production queues, and no synthetic evaluation shortcuts.
3. **Turnkey Reproducibility**: Any reviewer can clone the repo and execute `python scripts/run_evaluation.py` to reproduce headline benchmarks in under 15 minutes.

## 3. Local Environment Setup

### Prerequisites
- Python 3.11+ (Python 3.12 or 3.13 supported)
- Git
- Virtual environment (recommended: `venv` or `conda`)

### Installation
```bash
# 1. Clone repository
git clone https://github.com/NISHAKAR06/customer-support-agent.git
cd customer-support-agent

# 2. Create and activate virtual environment
python -m venv venv
# On Windows:
.\venv\Scripts\activate
# On Unix/macOS:
source venv/bin/activate

# 3. Install dependencies
pip install -r requirements.txt
pip install -r requirements-dev.txt

# 4. Configure environment
cp .env.example .env
```

## 6. Running Benchmark Evaluations

```bash
# Master pipeline: runs all training, smoke tests, and evaluation benchmarks:
python scripts/run_all.py

# Or run individual benchmark modules:
# 1. Evaluate baseline intent classifiers (Test split & Golden set)
python scripts/evaluation/evaluate_intent_models.py

# 2. Evaluate dense FAISS retrieval (Unconditioned vs Intent-Conditioned)
python scripts/evaluation/evaluate_retrieval.py

# 3. Evaluate grounded generation & safety barriers across 200 Golden samples
python scripts/evaluation/evaluate_generation.py

# 4. Evaluate LLM-as-a-Judge rubric & inter-annotator agreement
python scripts/evaluation/evaluate_judge.py
```
