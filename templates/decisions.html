Engineering Decision Log

Documented rationale, alternatives, and trade-offs for 12 foundational system decisions.

Decision Area Choice & Core Rationale Alternatives Rejected Key Trade-off
1. Single Brand Focus Select exactly ONE brand from the 3M Twitter corpus to ground in real, verifiable policies. Multi-brand aggregated training across distinct industries. Specializes deeply in one brand; not generic across unrelated products.
2. Thread-Level Data Split Split data strictly by conversation thread IDs to prevent conversational leakage. Random message-level train/test split. Requires precomputing the full conversational thread graph.
3. Hand-Labelled Golden Set Personally review and hand-label 150–250 real examples without synthetic shortcuts. Synthetic LLM-generated labels. High manual labeling time; smaller evaluation set size.
4. Two Baseline Systems Majority baseline + TF-IDF Logistic Regression for explainable benchmarks. Zero-shot LLM baseline or heuristic string matching. Requires maintaining three distinct model pipelines.
5. Dense FAISS Vector Store Sentence-Transformers (MiniLM) + FAISS index for sub-millisecond semantic search. Exact keyword matching or relational SQL LIKE queries. Requires offline vector store construction and RAM overhead.
6. LLM Provider Fallback Decoupled provider interface: Google Gemini primary with offline local fallback. Single vendor hardcoding in route handlers. Additional architectural abstraction layers.
7. Deterministic Validator Independent validation gate verifying non-empty, grounded, and policy-compliant replies. Relying purely on LLM system prompt obedience. Adds ~5–10ms validation latency per response.
8. Escalation Policy Matrix Rule-based routing using intent confidence, retrieval similarity, and risk phrases. Asking the LLM whether it should escalate. Requires calibrating thresholds during validation.
9. Vanilla HTML/CSS/JS FastAPI Jinja2 templates without heavy Node/React build toolchains. React, Next.js, Vue, or Angular SPA. Manual DOM manipulation for real-time streaming updates.
10. B2B SaaS Aesthetic Monochrome B2B support ops design inspired by modern shared inbox operations portals. Generic Tailwind templates or flashy dark cyberpunk AI themes. Requires disciplined custom CSS tokens and strict component hierarchy.
11. Real Pipeline Streaming Real-time SSE events tracking actual execution rather than mock progress bars. Client-side JavaScript setTimeout fake animations. Requires event pub/sub management in backend services.
12. Structured LLM Judge Strict JSON-schema rubric scoring Groundedness, Helpfulness, and Policy Fit. Unstructured qualitative text summaries. Requires JSON schema validation on judge outputs.
